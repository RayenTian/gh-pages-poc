How refit works when prefill and decode engines use different numbers of GPUs

PR #4801 (first of the Megatron prefill/decode stack) · permalinks at head 1a2eca34; before = main 5e271174; the caller that passes widths is in #5025 62868966

#4801 next to main's Dynamo refit with uneven widths one P/D interface

Three pages on this PR, one question each. This one: what the refit-width change adds, how it is set, and how ranks are laid out.

Before
Every generation engine had the same width, so engine i's GPUs started at i × width in the refit group.
This PR
Keeps one width per engine and starts each engine where the earlier ones end. Equal widths give exactly the old layout.
Status
Works, and changes nothing on main today: every fleet on main has equal widths. Uneven widths start in #5025. One open review ask: callers are tested only with equal widths (C5).
Background. After every training step, the trainer sends new weights to the inference engines over one NCCL group: trainer ranks first, then each engine's GPUs, engine by engine. Each engine must know the rank its GPUs start at. A prefill engine is limited by compute and often wants more GPUs (TP 4); a decode engine is limited by memory and often does fine with fewer (TP 2). Dotted words have a short explanation: hover or tap them.

The layout, old rule vs new

With engine widths (4, 2, 2), the old rule i × 2 starts engine 1 at worker 2, inside the prefill engine. The new rule adds up the widths before each engine. When an engine dies, the refit group is rebuilt from the survivors, packed one after another, while the worker list keeps every slot, so worker_offset still counts the dead engine's width.

How it is set: from one YAML key to the widths

Nothing new to turn on: the widths follow from each role's parallel layout. The only knob that makes them differ is a per-role override.

# the only knob that makes widths differ
policy:
  megatron_cfg: {tensor_model_parallel_size: 2, pipeline_model_parallel_size: 1}
  generation:
    backend: megatron
    dynamo: true
    disaggregation: {enabled: true, num_prefill_engines: 1, num_decode_engines: 2}
    dynamo_cfg:
      prefill_engine: {tensor_model_parallel_size: 4}   # decode keeps the shared TP 2
# driver, at setup (this PR adds all of it; #5025 calls it)
layout(role) = merged_inference_megatron_cfg(policy, overrides=dynamo_cfg.<role>_engine)
width(role)  = engine_width(role) = TP × PP                                    # prefill 4 × 1 = 4, decode 2 × 1 = 2
replica      = replica_width(layout, widths)                                   # 1 × 4 + 2 × 2 = 8 GPUs
roles        = engine_roles(layout, 8 GPUs, widths)                            # [prefill, decode, decode]
# #5025: one engine per role, then the refit group
shard_widths = tuple(engine.world_size for engine in engines)                  # (4, 2, 2)
full_fleet_membership(trainers=16) → plan_refit_membership(..., shard_widths)  # #4801 alone never passes widths

Real code: engine_width, replica_width, engine_roles (all in this PR); shard_widths and full_fleet_membership (in #5025). The same overrides live in trtllm_cfg.prefill_engine on main and vllm_cfg.prefill_engine in #4920 (see review comment C12).

How it works: the refit plan, before and after

Refit plan, before (main)

# driver, weight synchronizer: plan the refit group (also after a shard dies)
def plan_refit_membership(surviving, dp_size, total_workers, trainers):
    width = total_workers // dp_size                          # one width for every shard
    prefix = {s: i * width for i, s in enumerate(surviving)}  # ranks after the trainers
    return Membership(world=trainers + len(surviving) * width, prefix, width)
# driver, fan out the new group
vLLM:     leader = workers[shard * width]                     # first worker of the shard
Megatron: ranks for workers[shard * width : + width]

Refit plan, after (this PR)

# driver, same place; example: 16 trainer ranks, shards (4, 2, 2), shard 0 dead
def plan_refit_membership(surviving, dp_size, total_workers, trainers,
                          shard_widths=None):                        # no caller passes it yet
    widths = shard_widths or (total_workers // dp_size,) * dp_size   # (4, 2, 2)
    prefix = {s: i * width for i, s in enumerate(surviving)}
    for s in sorted(surviving): prefix[s] = next; next += widths[s]  # {1: 0, 2: 2}
    return Membership(world=trainers + next, prefix, widths)         # world = 16 + 4 = 20
def worker_offset(shard): return sum(widths[:shard])                 # 0, 4, 6: dead shards count
vLLM:     leader = workers[membership.worker_offset(shard)]          # C5: tested only with equal widths
Megatron: ranks for workers[worker_offset(shard) : + widths[shard]]

Real code: plan_refit_membership, worker_offset; callers vLLM L1288, L1337, L2033 and Megatron L526-L527. TRT-LLM on main (init_collective) and #4920's vLLM path compute the same running total on their own.

💬 review comment C5 — vllm_generation.py:1337 C12 — dynamo_config.py:89

So what. Every prefill/decode backend has to start each engine at the sum of the widths before it. TRT-LLM on main does it inside its own init_collective, never touching the shared refit plan, and it refuses any partial group. #4920 does the same for vLLM. This PR instead puts the widths into the shared RefitMembership, because #5025 makes each Megatron engine its own refit shard. That is safe on main, since equal widths give the old layout. But it makes three places that compute the same running total; one shared helper would serve all three. The review links work for others only after the review is published.
