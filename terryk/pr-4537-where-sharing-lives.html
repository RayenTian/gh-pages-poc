Who should decide which training rows share a prefix: the rollout reassembler, or Megatron?

NVIDIA-NeMo/RL #4537 with its Megatron-LM halves, #7914 (model forward) and #8152 (megatron.rl packing library). Main links pin defdaef4 (the PR's merge base); PR links pin 1110db98.

Main
Gym records each model call. call_selection picks the calls that train, and the rollout reassembler turns them into rows: one per rollout, or several per rollout with forest training (compaction, branches), sharing one reward and advantage. No row knows it shares tokens with another.
This PR
Adds one column, each row's first-prompt length, behind a flag on the same reassembler. Megatron then works out which rows share, from group id and prompt tokens, and shares only that first prompt. It refuses forest training.
Status
Proposed — draft only, not in #4537. The third column below is a design ask raised in the review. A draft of it, on top of the PR's branch, is open for critique: terrykong/RL#30.

Five pages on this PR — this one: which component should own the prefix tree.

Background. In the single-controller GRPO path, Gym runs the agent and records every model call with a link to the call it continued. call_selection decides which calls train. The rollout reassembler builds the rows. With forest training, one rollout can own several rows, and the advantage stage gives all of them that rollout's single advantage. Dotted words have a short explanation: hover or tap them.

finalize_group is the one place that sees the selected calls, their parent links, and the finished rows at the same time. #4537 leaves it almost untouched: it adds a shared_prefix_prompt_lengths column and nothing else. The Megatron worker then rebuilds the sharing from the group id and the prompt tokens, so it can only find one level: one prompt, many completions. And because setup refuses forest training, the runs whose rows share the most tokens (compaction and branches) cannot use the feature at all.

# reassembler actor: a subclass, picked by config (like selection_policy)
class SharedPrefixRolloutReassembler(RolloutReassembler):
    def row_extras(self, rows, selected_calls):                               # new hook on the base class
        # compare token IDs of the group's rows; parent links say where branches split
        prefix_row, prefix_len = longest_shared_prefix(rows, selected_calls)  # r1 → (r0, 340), r2 → (r0, 300)

SizeThe "who shares with whom" decision is about 20–40 lines today, all in Megatron-LM's megatron.rl. The PR's ~2,170 lines of Megatron worker code (packing, TP/CP, DP agreement, scatter-back) stay either way. The move changes the contract, not the amount of code.

Three things need care. Loss: in r1 the copy of A is context only, because r0 owns A's loss. When A becomes one shared node, its loss mask must come from r0. Advantages: the advantage stage reads LogicalRowTag per row, so the shared path must hand logprobs back to the original rows. It already does, by source-row index, and the new columns don't change that. DP sharding: forest groups differ in row count, so the equal-size rule in the group sharding has to go. Lifting the setup refusal alone is not enough.

So what. The tree is already known when rows are built: the reassembler has every call's parent. Building it there, as a reassembler subclass, gives every backend the same explicit tree instead of one prompt length. That is what forest runs (compaction and branches) need, and what Automodel would read later. It saves little code: Megatron keeps its packing. Forest runs also need group sharding that accepts uneven groups, and deeper trees need Megatron's model code to run them.
