Two pages on this PR, one question each — this one: why the engine build fails, and what fixes it.

The Dynamo worker adds two fields to Megatron-LM's engine config through _inference_config_overrides(). The worker merges them in and calls InferenceConfig(**kwargs). At the pinned Megatron-LM, InferenceConfig is a plain dataclass with kv_transport_backend but no disaggregation_role. A dataclass refuses unknown keyword arguments, so the call raises before the engine exists.

What the engine build sees

The tests miss it because the mixin test only compares the returned dict. It never hands that dict to a real InferenceConfig. The "is the Dynamo integration installed" check also passes at the pin, because the module it imports does exist there.

The fix — proposed, not in the PR

Where the fix lands: Megatron-Bridge first, then RL. Bridge moves its Megatron-LM pin to a commit that contains 84c7f168. RL then bumps its Bridge submodule (on Bridge's tracked main) and uv.lock in this PR, and adds one CPU test. No change to the RL worker code.

Nothing below is implemented.

The test, as pseudocode (proposed, not run)

# tests/unit/models/generation/test_megatron_dynamo_worker_mixin.py, mcore lane
@pytest.mark.parametrize("role", ["prefill", "decode"])
def test_overrides_build_a_real_inference_config(role):
    overrides = _bare_worker(role)._inference_config_overrides()
    InferenceConfig(**overrides)                  # fails today with the TypeError above

Do not just delete the field. Without it, a decode engine of a hybrid (Mamba) model keeps the prefix-cache budget that prefix_caching_mamba_gb gives, and the pinned Megatron-LM then refuses the KV handoff at the first refit. The field is what turns that budget off for decode.

So what. As written, the whole six-PR stack ships an engine that cannot be built: the error moves from setup to the first refit, but it always fires. The fix is a version bump plus one small test, not a code change. It needs Bridge's pin to move first, so it should start now rather than after PR 5 turns the feature on.
