Three pages on this PR, one question each — this one: why one sampler can stall.

Background. Each finished group is stamped with a weight version: the oldest version of the policy that generated any of its samples (group_min_wv). If new weights land while a batch is still generating, one step's groups split across two versions. The weight_fifo sampler only takes groups from the oldest version still in its window (target_version = min(in_window)), and it moves on to a newer version only once the older one is empty. Dotted words have a short explanation: hover or tap them.

4 groups, two weight versions, multiple 2

The "This PR" row is a real run of WeightFifoSampler.select at b52f74b with group multiple 2: polls took [2, 0, 0] groups, leaving weight versions [0, 1]. With multiple 1 the same buffer gave [3, 1] and emptied.

The fix — proposed, not in the PR

Nothing below is implemented. It is the suggestion in review comment C2.

Where the fix lands: RL only, setup. One check at the end of resolve_grpo_chunk_alignment. Setup already rejects single-weight samplers for the same kind of reason: with a drop budget (config.py:1337) and with dynamic sampling (config.py:1638).

The fix, as pseudocode (proposed; run on CPU)

# setup, once, when the trainer is built
def resolve_grpo_chunk_alignment(cfg, dp):
    m = resolve_grpo_group_multiple(cfg, dp)          # 2 here
    ...                                               # step size and cap checks
    if m > 1 and streaming and sampler_reads_one_weight_version:
        raise ValueError("... cannot align chunks to 2 prompt groups ...")
    return m

Full-batch weight_fifo (floor = num_prompts_per_step) and any run with m = 1 still pass. The check's test fails at head and passes with the fix.

So what. Low priority: no shipped recipe runs weight_fifo with streaming. But the failure mode got worse: what used to fail fast now ties up the whole allocation until the watchdog fires. Rejecting the combination at setup turns it back into a fast, clear error. review comment C2 · config.py:2035
