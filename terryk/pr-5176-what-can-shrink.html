Four pages on this PR. This one: which lines can go, and why each cut is safe.

Two asks do most of the work. C15 drops the PR's three settings (prefix_writer_actor, prefix_write_pipeline.enabled, direct_column_encoding), which today allow six ways to write a cut, and picks the new path whenever the run can use it: text-only capture on TransferQueue simple. The old path stays only for media capture and other TQ backends, which the new one does not support (L851-L856). C2 keeps the NumPy byte views, because Ray 2.58 copies torch tensors (and so a TensorDict) through torch's own pickle but hands NumPy arrays to the actor in place (≈ 45 + 14 ms against ≈ 2 + 0 ms for a 128 MiB batch). It shrinks them to two helpers and replaces the 94-line RayPrefixWriterClient with a thin wrapper.

So what. The three speedups the PR measured all survive: the column encoder, the prepare/write overlap and the separate writer process, and they become the default. What goes is a no-copy bridge written longer than it needs to be, metrics nothing reads, and settings that let a run pick a slower path for no reason. The PR would then be about +1,723 lines. A further option is to split it: encoder + pipeline first (the bigger win), then the writer actor.
