Which masked rollouts still move the GRPO baseline, under each masked_reward_policy

NVIDIA-NeMo/RL #4968 (adds exclude_infra), a follow-up to #4160. Code links pinned to head 956c6f04. Background on the first two values: who votes (#4160).

Before
Two values. include (default): every masked rollout's reward still counts in its group's baseline and std. exclude: no masked rollout counts, even when the policy caused the mask.
This PR
Adds a third, opt-in value, exclude_infra: a masked rollout counts only if the environment blamed the policy for it.
Status
Open PR, not merged. The default stays include, so no shipped recipe changes. The review raises no training bug, only doc and test fixes (see the end).
Background. In GRPO each prompt gets several rollouts. A rollout's advantage compares its reward with its siblings'. A masked rollout never trains, but under include its reward still shifts its siblings' baseline. NeMo-Gym also sends a failure_kind string saying why it masked a row. The PR splits masked rows by that string: a kind in grpo.policy_failure_kinds (for example agent_timeout) is the policy's fault; any other kind, or none, is an infrastructure failure. Dotted words have a short explanation: hover or tap them.

One prompt group, five rollouts. A, B, C are normal. D was masked because the agent timed out (a policy kind). E was masked with no failure_kind, for example a judge error, so its reward is a meaningless 0 or 1. The numbers are from running the PR's real estimator (GRPO, leave-one-out baseline, rewards normalized by std).

Where each value does the work

include and exclude decide who votes at the advantage step. exclude_infra does not add a third rule there. It works earlier: when Gym's results arrive, it gives each infrastructure-failed row a dataset weight of 0, the same weight an over-length prompt gets. From then on it is just include, which never lets a zero-weight row vote. That is why no trainer's advantage math changed.

Rollout builder, after (legacy, async and TQ trainers)

# per prompt group, when Gym's results arrive
mask_sample = flags(results)                 # Gym: this row gets no loss
if policy == "exclude_infra":
    infra = mask_sample & (kind not in policy_failure_kinds)  # infra_failure_flags
    loss_multiplier[infra] = 0                   # same weight as an over-length prompt
    metrics["infra_failure_sample_rate"] = infra.mean()

# advantage step, every trainer
def _advantage_valid_mask(loss_weight, cfg, dataset_weight):
    if cfg.masked_reward_policy == "include":

What to take away, and what the review asks

Only under include does a meaningless reward (E) move the advantages of rollouts that train. exclude_infra removes that, and unlike exclude it keeps a policy-caused failure (D) in the baseline, because a timeout is a real result. It is opt-in, so existing recipes do not change.

The review has no training bug. It asks for:

  • The guide and one test say OSWorld masks evaluator errors with no kind. At RL's Gym pin, OSWorld tags them infrastructure_error. This is wording only; the row is still left out.
  • Shorter comments and docstrings, 1–2 lines each.
  • A test that can tell a per-rollout infra_failure_sample_rate from a per-row one.
  • A fix to the PR description: the SWE agents do tag limits and timeouts with policy kinds, so those rows vote under exclude_infra, as under include.
