How the health check learns that one HTTP frontend died

PR #5075 · builds on #5074 (merged) · PR code at abb8603, main at 9ec0986 · background: how many frontends share one engine

Before
A frontend process could die while its vLLM worker lived on. The health check only asked the worker, which always said "alive", so the shard stayed in rotation. Because of that, main refuses to start with several frontends and fleet health both on.
This PR
The worker's is_alive also checks each frontend process and raises if one is gone. The health check counts that as a failed probe, and after 3 in a row the shard is marked dead and taken out of rotation.
Status
The fix works in the code. Open: not mergeable yet. The branch is built on an old copy of #5074 and must be rebased. The review lists 4 things that must change during the rebase (below). Not run on GPUs yet.
Background. With http_api_server_count: 8, each vLLM worker (a Ray actor that owns the GPU engine) serves HTTP through 8 frontends: 1 server thread inside the worker plus 7 child processes it spawns, named NRL-HTTP-1 … NRL-HTTP-7. They share one listening socket. Every 5 s the controller's fleet health check calls is_alive on each shard's lead worker. Dotted words have a short explanation: hover or tap them.

The fix, as pseudocode

Before (main today)

# vLLM worker actor, answering the controller's probe
def is_alive():
    return True                                   # the actor answered, so "alive"

After (this PR)

# vLLM worker actor, answering the controller's probe
def is_alive():
    if pool is not None:
        pool.check_health()                       # C1: should reuse main's raise_if_unavailable()
    return True

# the frontend pool, same actor, same event loop
def check_health():
    if failed: raise "pool failed"                # C1: main already keeps this as _failure
    for p in children:
        if not p.is_alive(): raise f"{p.name} exited"

# controller, every 5 s, all shards at once
try: lead_worker.is_alive()                       # unchanged
except ActorDied: mark DEAD now
except Exception: record_probe(ok=False)          # the new raise lands here

Real code: VllmAsyncGenerationWorkerImpl.is_alive, MultiAPIServerPool.check_health, the probe loop.

What the rebase must change

Main now has the merged #5074, so the branch conflicts. Four items, all in this PR:

  1. One failure flag, and let "stop" finish. Main already records a pool failure in _failure / raise_if_unavailable(); the new _failed would be a second copy. Also, at the end of a run with a dead frontend, shutdown() sends "stop", which raises on the dead child, so the worker's own cleanup is skipped. This PR makes that the normal way such a run ends.

    🔴 review comment C1 — multi_api.py:185

  2. Delete main's guard that blocks this setup. Main raises at setup when there are several frontends and fleet health is on, and the message links this PR. Every failover test run sets both, so all 3 would fail. CI cannot see this, because the script skips itself on the 2-GPU runners. The docs state the same old rule.

    🔴 review comment C2 — grpo_sc_gym_router_failover.sh:140

  3. Move the new unit tests into a file CI runs. No test lane picks up test_multi_api.py; main renamed it to test_vllm_multi_api.py.

    🔴 review comment C3 — test_multi_api.py:183

  4. Turn off Ray's log de-duplication in the test. The script finds which process to kill by reading the "NRL HTTP frontend ready" lines from the log. Ray ignores every word with a digit when it compares lines, so the two shards' lines look identical and one shard's lines are hidden. If that is the shard the script picked, the run fails, roughly half the time. One line, export RAY_DEDUP_LOGS=0, fixes it, as another chaos test already does.

    🔴 review comment C4 — grpo_sc_gym_router_failover.sh:37

So what. The idea is right and small: a dead frontend now takes its shard out of rotation in about 15 s, before the next control command shuts the engine down with requests still running on it. But the branch only makes sense after a rebase that removes main's guard. The only end-to-end proof is a 3-GPU test that CI skips, so after the rebase someone has to run it by hand.
