The Megatron prefill/decode stack: what each of the 6 PRs does, and what works after it

NVIDIA-NeMo/RL · #4801 → #4912 → #5023 → #5024 → #5025 → #5097 · each PR is reviewed against the one below it · state as of 2026-11-23

The goal. Serve NeMo RL's Megatron inference as separate prefill and decode engines behind one Dynamo frontend, with weights pushed from the trainer after every step (a refit), the same way vLLM already runs behind Dynamo on main. Turned on with policy.generation.backend: megatron + dynamo: true. Dotted words: hover or tap.

What to keep in mind while reviewing. PRs 1–4 change nothing on main at run time: setup refuses dynamo: true until #5025. So a bug in 1–4 usually shows up only once #5025 turns the feature on, and the fix can live in the PR that wrote the code even if it is not reachable yet. Two needs reach outside this repo: the pinned Megatron-LM lacks a field #4912 uses and a class #5097 uses, so both are asked to fail early with a clear message rather than bump Megatron-LM inside the stack.
