Six pages on this PR — this one: which process and class does each step, and what crosses between them.

Background. In single-controller GRPO, Gym runs the agent and records each model call. The rollout reassembler joins the calls into training rows and writes them to TQ. The driver splits the batch across data-parallel ranks, and each Megatron worker fetches its rows and runs the model. Dotted words have a short explanation: hover or tap them.
Two different things, built in two places. (1) Which rows share which tokens is a few numbers per row. This PR writes one, the prompt length, in the reassembler. The proposal writes four, the tree, also in the reassembler (C11). (2) The packed shared forward, meaning the SharedPrefixLayout plus the gathered token, position and scatter tensors, is built in the Megatron policy worker, in memory, for every forward pass (steps ⑤–⑥). It depends on what only the worker knows: its rows, the token budget, and TP/CP. Neither version stores it in TQ.

The figure follows one group (prompt A, 120 tokens, completions 50, 30 and 20) through each process. Rows in TQ stay dense in both columns, so the value model and the teachers, which read the same rows, never see a different structure. What changes is who decides the sharing, and where its code lives.

The worker's step, as pseudocode

This PR

# Megatron policy worker, every get_logprobs / train call rows = build_shared_prefix_rows(input_ids, prompt_lengths, group_ids) # prompt tokens → Python tuples units = plan_shared_prefix_execution_units(rows, budget) # full-length budget, even without MTP n = all_reduce_max(len(units)); units = align(units, n) for u in units: tb = materialize_shared_prefix_layout(input_ids, u.layout) # megatron.rl lay = to_core_layout(tb.layout) # copy rl type → core type out = model(tb.packed_input_ids, shared_prefix_layout=lay) logprobs[u.rows] = scatter(out) # back to [rows, S−1]

Proposed

# Megatron policy worker, every get_logprobs / train call roots = tree_roots(slot, parent) # columns from the reassembler (C11) units = plan_units(rows, budget, full_len_check=mtp_runs) # megatron.core.datasets.shared_prefix (C13, C14) n = all_reduce_max(len(units)); units = align(units, n) for u in units: tb = build_tensors(input_ids, u.layout) # returns core's SharedPrefixLayout lay = to_core_layout(tb.layout) out = model(tb.packed_input_ids, shared_prefix_layout=tb.layout) logprobs[u.rows] = scatter(out) # unchanged

The driver side moves the same way: preshard calls nemo_rl/data/packing/shared_prefix/shards.py, and setup calls one validator (C17).

So what. In both columns the rows in TQ stay dense, so every other model that reads them keeps working. The proposal moves two decisions: the reassembler decides which rows share, once, and the code that builds the shared forward lives in megatron.core instead of megatron.rl. The RL driver then needs no Megatron install, and forest training becomes possible.
