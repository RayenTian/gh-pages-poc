Two pages on this PR, one question each — this one: the case the fix still misses.

Background. With dynamic sampling, a prompt whose answers all score the same is thrown away and a spare prompt replaces it. When the data runs out there may be no spare left. The step is then allowed to close short, and its target drops by one. Page 1 explains the group multiple m. Dotted words have a short explanation: hover or tap them.

Take the shape of the shipped dapo-nanov3.5 single-controller recipes: 8 prompts per step, full batch, group multiple m = 2. At the end of data one prompt is filtered with no spare, so _pop_filtered_replacement marks the step short and _target_groups_for_step returns 7. The pump asks the sampler for exactly 7 groups, in whole multiples of 2. No such number exists, so _finalize_selection raises on a step the controller had already said may close short. The drop-budget warning does not fire, because no drop budget is involved.

Target 8 → 7, in multiples of 2

What would fix it — proposed, not in the PR

Nothing below is implemented. It is the fix asked for in review comment C1.

Where the fix lands: RL only, one line in _target_groups_for_step, plus one line in a test that builds the controller by hand.

The fix, as pseudocode (proposed; run on CPU)

# train pump, every time it needs the step's target
def target_groups_for_step(step):
    target = num_prompts_per_step - shortfall[step]  # 8 - 1 = 7
    if step in steps_allowed_short:
        return target                                # 7: no multiple of 2 fits
        return target - target % m                   # 6: closes on whole multiples
    ...

Every reader of the target then agrees: the pump's while loop, the select bound, and the PPO and Forest checks (both have m = 1, so they do not change). A target that rounds to 0 closes with no groups and is skipped with no optimizer update.

So what. Any GRPO run with dynamic sampling, the in_order or ready_first sampler and m > 1 that reaches the end of its data can die on its last step instead of finishing cleanly: it only takes an odd number of filtered prompts with no spare. The shipped dapo-nanov3.5 recipes have exactly that shape; their 10-step limit usually stops them first. The fix is one line plus a regression test, so it belongs in this PR. review comment C1
