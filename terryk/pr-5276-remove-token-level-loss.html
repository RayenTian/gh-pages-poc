Four pages on #4946 and the two PRs stacked after it — this one: what happens to configs that still use the old key.

Before
loss_fn.token_level_loss: true/false still works on main, with a FutureWarning (page 1).
This PR
Removes the key. Any config that still has it, even with value null, fails at startup with the fix in the error. Moves all 31 checked-in configs to loss_fn.normalization.
Status
Proposed — open, not reviewed yet. It lands after #4947; its "Files changed" tab also shows #4947's diff until that merges.

What an old config sees

Old config lineWrite instead
token_level_loss: truenormalization: global_token_mean (or leave both out: it is the default)
token_level_loss: falsenormalization: sequence_mean
token_level_loss: nulldelete the line (the shipped YAMLs had this after #4946)

This follows the repo's rule for removed config: one reject_outdated_* function in outdated_config_checks.py, called before the config is built, so the user sees how to migrate instead of a schema error.

What changed in the code

Where it lands: RL only. outdated_config_checks.py, loss_functions.py, 31 YAMLs, docs, two test scripts' command-line overrides, and the numeric golden file (selector only).

The one catch: bootstrap snapshots

Before a run saves its first trainer checkpoint, it can resume from a bootstrap snapshot. That snapshot stores a fingerprint of the whole config: every key counts unless it is on a short skip list. A snapshot saved by #4946's code holds loss_fn.token_level_loss: null. After this PR that key does not exist, so the fingerprints differ and the resume is refused, with a diff line like loss_fn.token_level_loss: None -> <missing>. The training math is the same; only the config's shape changed.

The fix, from the GRPO guide this PR updates: resume that snapshot with the NeMo-RL version and config that wrote it, let it save a trainer checkpoint, then upgrade. Runs that already have a trainer checkpoint are not affected.

So what. After #5276 there is one way to pick the average: loss_fn.normalization. Before upgrading, search your own configs and command lines for token_level_loss and replace it using the table above. If a run is still before its first trainer checkpoint, let it reach one on the old version first.
