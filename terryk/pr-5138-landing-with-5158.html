Why there is no behavior conflict

QuestionAnswer, from the code
Is the new key per harness?No. allow_system_suffix sits in the one global token_id_capture block that _spinup builds, with all_agents: True. Every harness in a #5158 run gets it.
Is one global key safe when only one harness adds system messages?Yes. The key only lets Gym propose more candidates. RL's prefix check runs on each call, using that call's messages and the policy's one chat template. A harness that never adds system messages never reaches it.
Can saved tokens leak from one harness to another?No. Gym compares a call only with earlier records from the same lineage scope (own_records, at the bump's Gym). #5158 keeps a whole group on one harness.
Resume with both?#5158 keeps a restored group on its harness, or stops the run. On #5138's side, re-rendering a call gives the same tokens, so the same decision. A saved cut whose prefix no longer matches is regenerated.
Shared test file?Both change tests/unit/environments/test_nemo_gym_utils.py, and that merges cleanly today. C2's new parameter on test_spinup_passes_parent_resolution_to_gym could cause a small text conflict later; no logic depends on the other PR.
