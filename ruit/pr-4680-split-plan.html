05两种方法共用的部分：loss 基类、trainer 分发点、共用算子已有代码的改造 · 依赖：PR 01 · 方向已定，细节待推敲

refactor(xtoken): extract shared cross-tokenizer loss base and trainer dispatch

原 PR 里有相当一部分不是新增 CSD，而是改造 X-Token 已有的 trainer 和 loss，让它能容纳第二种方法。这部分先做成一个只有 X-Token 的重构，合入时全部被 X-Token 使用。

为什么这样切

X-Token loss 本身已经有两种比较方式（整体投影后算 KL，或先处理一一对应的 token 再处理其余部分），分叉点在一个方法里。原 PR 的 CSD loss 是从 X-Token loss 复制出来再改的：分叉点换成 CSD 的计算，其余骨架相同。两个类里同名的方法，4 个逐字相同或几乎相同，另外 5 个相似度在 0.7 到 0.85 之间，合计每个类约 360 行。所以 CSD 更接近“同一个框架里的第三种比较方式”，而不是一个并列的独立算法。

纳入范围

  • 抽出共用的 loss 基类：多 teacher 聚合（sum、averaged_logits、select_teacher）、学生 CE、同 tokenizer 的 KL、动态权重、指标。X-Token loss 改成它的子类，只保留自己的两种比较方式。
  • trainer 里按方法选择 loss 和 collator 的分发点，本阶段只有 X-Token 一个分支。
  • 两种方法都要用的基础算子（如 CP 布局转换），前提是 X-Token 的路径在本 PR 里改用它们。

本阶段边界

  • 不引入任何 CSD 代码或 CSD 配置键。
  • X-Token 用不到的算子不进本 PR，跟着第一个用它的 PR 走。

风险

基类要采用 CSD 那一版的实现（它是 X-Token 版的超集，例如跨进程求和用传入的进程组而不是全局组）。这会改变 X-Token 的代码路径，不是纯移动，要有前后对照。

验收要求

  • 同一输入下，重构前后的 loss、梯度和指标逐项一致。
  • X-Token 单测全过；两个 X-Token nightly 做重构前后的对照。
  • 多 teacher 聚合、学生 CE、同 tokenizer KL 在仓库里各只有一份实现。
  • Recipe：不新增。现有的两个 X-Token nightly 就是重构前后的对照。

粗估 2,000 到 2,500 行（含测试），未实测。
