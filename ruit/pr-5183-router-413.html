lent engines vs inline413 on large requests

Two pages on this PR, one question each. This one: a bug the review found in the new request path.

Background: the words on this page The router sits between NeMo Gym and the vLLM engines. This PR tells every engine to use priority scheduling, and has the router mark training requests so they start before validation requests. Dotted words have a short explanation: hover or tap them.

To mark a request, _forward calls await request.read() and rewrites the JSON (_with_priority). aiohttp only lets read() take 1 MiB unless the app sets client_max_size, and web.Application() does not. Text prompts stay far below that. A chat request with images does not: the images travel inside the body as base64 text.

The router sets one header and goes back to passing the body through. Run on CPU with this change: the 2 MB request passes, the stub engine sees X-Vllm-Priority: -1, and the body is unchanged. The vLLM side was checked by reading its source, not by running an engine. A smaller change also works: pass a large client_max_size to web.Application; it keeps the JSON rewrite on every request.
