Teaching the student the whole answer, scoring only part of it: how this PR splits chat supervision into two masks

Companion illustration for NVIDIA-NeMo/RL #4728 (cross-tokenizer collator options). All producer permalinks pin the PR head d7e38de; the consumer, which lands in the follow-up #4680, pins 22ebcf7.

Before
In chat mode one mask (token_mask) drove both losses: the student learned (cross-entropy, CE) and was scored against the teacher (knowledge distillation, KD) on the same narrow span — the final answer text plus its end-of-turn token.
This PR
Adds an off-by-default option ce_covers_assistant_turn. When on, CE covers the whole final assistant turn (role header, the template's empty think block, answer, end-of-turn, newline), while KD keeps the narrow answer span under a new key kd_token_mask.
Status
Shipped here, switched off. This PR only adds the option and the new output key; nothing turns it on. The code that reads kd_token_mask arrives in #4680.
Background. A chat template turns a conversation into one string of tokens, e.g. Qwen's ChatML: <|im_start|>assistant … <|im_end|>. The collator builds the training batch: it decides which tokens the model is trained on by handing back a 0/1 token_mask. CE is the plain next-token loss (copy the reference text). KD matches the student's probabilities to a teacher's over the same positions. Until now both read the one token_mask, so they always covered the same tokens.

With a reasoning model you often want to teach the student to reproduce the fixed scaffolding the template emits — the <|im_start|>assistant header, the empty <think>…</think> block — but you do not want to score that boilerplate against a teacher, because it carries no real signal. CE should widen to the whole turn; KD should stay on the answer. One mask cannot say both things, so this PR keeps token_mask for CE and emits a second mask kd_token_mask for KD (collate _call_chat L485-496). The turn boundary is found by re-rendering every message except the last and checking it is a prefix of the full render (_final_turn_start L411); anything ambiguous raises instead of guessing.

How the split is wired — and why it is safe half-built

The producer is the whole feature in this PR: when the option is on, stash the old narrow mask as kd_token_mask, then widen token_mask to the turn. When the option is off, neither line runs and the batch is byte-for-byte what it was before — no extra key.

# nemo_rl/data/cross_tokenizer/cross_tokenizer_collate.py L485-496 (this PR, d7e38de) if self.ce_covers_assistant_turn: turn_starts = ... # first token of the final turn turn_mask = (positions >= turn_starts).long() out["kd_token_mask"] = out["token_mask"] # keep narrow answer mask for KD out["token_mask"] = (attention_mask * turn_mask) # widen CE to the whole turn

The consumer — the trainer that packs the batch and the loss that reads it — lands in #4680, not here. It reads the new key with a fallback to token_mask:

Where it lands: the producer is here (#4728), the consumer is in #4680. This PR ships the collator option and the kd_token_mask key. The trainer pack, the loss read, and the Megatron / Automodel data paths that forward the key are all in #4680 — each using the same .get("kd_token_mask", token_mask) fallback.
Why shipping the two halves apart is safe, not a silent bug. It would be a bug if the collator could emit the split while some old consumer ignored it — KD would quietly score the wrong, wider span. That cannot happen here for two reasons. First, the option is off and nothing in this PR turns it on, so the collator never emits kd_token_mask yet. Second, every consumer reads it as .get("kd_token_mask", token_mask): when the key is absent, KD falls back to exactly today's mask. And ce_covers_assistant_turn and its reader land together in #4680, so there is no release where one exists without the other. A grep for kd_token_mask in this PR alone finds only the writer and looks like a dead output — the fallback in the follow-up is the piece that makes the staged rollout correct.
