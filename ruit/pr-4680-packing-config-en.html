Background: lockstep packing puts the same group of samples into the student's and the teacher's own sequences. The current implementation excludes architectures with recurrent state, such as Mamba/SSM, so the model config that will really be loaded must be checked before startup.

The current resolver, when it sees a remote model_name and a local tokenizer directory that has a config.json, reads the latter instead; the real backend still loads by model_name. A model config that sits next to a tokenizer directory is not guaranteed to describe this model.

The input did not change, yet the check saw a different model

The reproduction uses a real public recurrent model config and its original tokenizer. The real AutoTokenizer confirms the full vocabulary, special tokens and several encodings are identical; adding just one unrelated dense config.json makes the real architecture exclusion check let it through.

Suggested fix: read from the model source — not merged

Change only RL's config resolver. Always resolve the architecture by model_name, the same as the backend; keep the existing overrides and offline options. No change is needed to tokenizer files or upstream libraries.
