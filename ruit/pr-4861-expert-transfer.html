Two pages on this PR. Feature comparison first; confirmed loader bug second.

Background. Training updates the model in Megatron; TRT-LLM generates the next answers. A refit copies the updated weights between them. A mixture-of-experts model keeps many separate expert networks; expert parallelism (EP) assigns each expert to a GPU. Dotted words have a short explanation: hover or tap.

The default collective receiver gets full tensors on every generation rank. The new receiver gets only its own expert slices, then converts them into loader-ready weights. Attention and other weights still use the existing packed broadcast.

Executed CPU illustration: six experts, three destination ranks, two experts per rank. Values mark the first entry of each [5,7] expert tensor. This checks the slice calculation, not GPU transfer or quantization.

Where the paths meet

Both preserve the engine’s finalize / finish update bracket. Inside that bracket, the collective path uses the generic model loader; reshard can load expert modules directly and keeps generic reload as a fallback. The second page explains why Qwen3 needs that fallback.
