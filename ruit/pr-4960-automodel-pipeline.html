Two jobs, two owners. Automodel builds and runs the neural network. NeMo RL trains it using losses and token logprobs—the log of each token's probability. Pipeline parallelism (PP) divides successive model layers across workers; a microbatch is the small group of rows they process at once.

The new setup gives each worker one stage. Its schedule moves each microbatch through those stages, then the last-stage callback sends logits—the model's token scores—to the same loss and logprob code as PP1. The optimizer update stays in the policy worker.

Data above comes from a CPU planning trace using the PR's real planning and input helpers. Activation shapes are code contracts, not measurements. CUDA movement and a single data-parallel collective were mocked; no model or pipeline schedule ran. Data-parallel workers train on different rows and synchronize gradients.

Why the new path adds four masked rows

With one row per microbatch and five microbatches per call, the planner rounds 11 real rows up to 15 rows. The four added rows copy the first row, with zero sample and token masks; they keep fixed-size calls running without adding training targets. A larger data-parallel shard can make the planner add more calls. For logprobs, the last stage removes added rows and broadcasts the result.

The tradeoff: split model execution across workers, pay for stage communication and padded calls. The paths meet at loss processing, while execution and full-model weight export remain different.
