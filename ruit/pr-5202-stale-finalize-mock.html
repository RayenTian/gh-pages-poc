Two pages on this PR — this one: a test the feature change leaves failing, and the one-line fix.

Before
On the committed path, the per-step "no reward signal" tally read only finalized.reward_observations — a field the test's stand-in object already had.
This PR
The same tally now calls _voting_rewards(finalized), which also reads reward_mask_sample, reward_truncated and loss_multiplier. The real object has all three; one existing test's stand-in does not.
Status
Open — not fixed in this PR. The test test_actor_path_releases_generation_permit_before_finalization raises AttributeError in CI. Flagged in review; the one-line fix is below.

The production code is correct: the real FinalizedGroup always carries reward_mask_sample, reward_truncated and loss_multiplier (reassembler :200-202). The problem is only in a test: test_rollout_pump.py mocks the finalizer with a bare SimpleNamespace (:1795) that only has valid_row_count, total_row_count and reward_observations. After the group commits, the pump computes its reward metric through _voting_rewards(finalized) (:1944-1950), which reaches for the three missing fields.

Where it breaks

I reproduced it directly, independent of any Ray cluster: ctrl._voting_rewards(SimpleNamespace(valid_row_count=1, total_row_count=1, reward_observations=[])) → AttributeError: 'types.SimpleNamespace' object has no attribute 'reward_mask_sample'. On the parent commit the committed-path tally was rewards_carry_no_signal([row.reward for row in finalized.reward_observations]), which needed only reward_observations — so the test passed before this PR and fails after it.

The fix — add the three fields to the mock

Where the fix lands: one test file. test_rollout_pump.py _delayed_finalize (:1795). No source change: production is already correct — the real object carries all three fields. This is a stale test stand-in, not a logic bug.
