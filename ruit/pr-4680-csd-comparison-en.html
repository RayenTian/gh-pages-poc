Background: distillation makes a student learn from the output of a frozen teacher. A tokenizer cuts text into the IDs a model uses; when two tokenizers cut differently, the outputs cannot be compared column by column by ID. REST collects the leftover probability into one class.

CSD reuses the shared collator and the character-span aligner, and adds two-way sub-token tables, so both sides' probabilities are compared on the same text events. What does the default KD term change?

M is the projection matrix, KX is the set of teacher tokens X-Token selects, and 𝓔 is the set of tokens or token chains both sides can express in CSD. Only the KD term inside one chunk is shown; temperature, normalization across chunks and floating-point guards are left out.

D_{\mathrm{X}}=\sum_{v\in K_X}q_{t,v}\left(\log q_{t,v}-\log\htmlClass{t1}{p_{s\to t,v}^{M,K_X}}\right)
D_{\mathrm{CSD}}=\mathrm{JSD}_{1/2}\!\left(\htmlClass{t2}{p_s^{\mathcal E+\mathrm{REST}}},\htmlClass{t2}{p_t^{\mathcal E+\mathrm{REST}}}\right)

In the first formula, p is the student's projected probability averaged over the chunk and then renormalized; q is the teacher's per-position log-softmax averaged over the chunk and then exponentiated, without renormalizing. So q is not called a full probability distribution. The in-chunk aggregation code is not the same treatment as the shared-event probabilities in the second formula.

X-Token defaults to P-KL, projecting onto the teacher vocabulary; CSD defaults to JSD, comparing shared events and REST. The full CSD KD term is normalized by the global number of valid chunks, multiplied by the temperature squared, and weights non-1:1 chunks ×5 by default; then the student CE is added. The default dynamic scaling scales KD by the CE/KD size ratio, with no gradient through the ratio.

The default K=128 means each position mostly sends the 128 teacher entries with the highest probability; it does not only save communication, it also changes the set of events compared, and REST keeps the leftover probability.
