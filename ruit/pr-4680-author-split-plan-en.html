2. Folder layout: today and proposed

Today (in PR #4680)

  • Each area keeps X-Token and CSD in separate folders, named after the method. Only nemo_rl/data/cross_tokenizer/ already holds both.
  • The trainer and the x_token/ helpers serve both methods but are named after X-Token.
  • run_csd.py just calls X-Token's entry point with csd.yaml.
  • The PR renames one file: the guide, which now covers both methods.

Proposed: one runner, one trainer

  • One runner and one trainer serve both methods, with neutral names.
  • Each method keeps its own loss and tools, under cross_tokenizer folders.
  • The code inside stays the same; only names, folders and the imports that point to them change.

3. How every PR stays safe to merge

Every PR is cut from current main and must pass the full CI on its own before it merges.

  • No PR calls code that isn't already on main or in that same PR, so nothing breaks between merges.
  • X-Token keeps working at every step. PRs that touch X-Token code also run both X-Token nightlies.
  • PR 1 brings two X-Token bug fixes: teacher scoring with context parallelism (one sequence split across several GPUs), and the strict exact-map rule. The X-Token nightly recipes are unaffected.
  • New CSD recipes follow main's current naming (-automodel-, not -dtensor-).
  • PR #4680 becomes a frozen draft for reference. It is closed, not merged, once the last piece lands. If packing waits, it stays open as packing's reference until then.
