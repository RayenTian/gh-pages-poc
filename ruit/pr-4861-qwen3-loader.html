Two pages on this PR. Feature comparison first; confirmed loader bug second.

Background. A weight mapper matches checkpoint tensor names to model modules. This PR’s direct expert loader calls a preprocessing method before touching the expert modules. The Qwen3 MoE mapper and Qwen3.5 mapper inherit different implementations.

With direct expert loading enabled by default, Qwen3 reaches a call its inherited method does not accept. CPU execution of the actual extracted methods produces TypeError: preprocess_weights() got an unexpected keyword argument 'allow_partial_loading'. This happens at the first expert flush.

What would fix it — proposed, not in the PR

Nothing below is implemented in the PR.

Where the fix lands: RL only, source and tests. Guard the direct loader for the Qwen3.5 mapper, and give the existing mock fixture that mapper’s real type. TRT-LLM needs no change for this repair: RL’s generic reload fallback already exists.
