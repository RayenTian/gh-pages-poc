背景：蒸馏让学生学习冻结教师的输出。tokenizer 把文字切成模型使用的编号；切法不同，就不能直接按编号逐列比较。REST 将剩余概率收成一类。

CSD 复用 共享 collator 和 字符跨度对齐器，新增 双向子词表，用相同文本事件比较两边的概率。下图的 token IDs 和分块来自真实 tokenizer；“你好”前面的 A 为两边提供预测上下文。

同一句话，在哪里比较？

学生 tokenizer 固定在 4e20de36，教师固定在 1cfa9a72。“你好”实际是学生位置 [1,2] 对教师位置 [1]；“世界”是位置 [3] 对 [2]，全部对齐正确。此处展示分块，不声称跑过模型。

默认 KD 项改变了什么？

M 是投影矩阵，KX 是 X-Token 选中的教师 token 集，𝓔 是 CSD 两边都能表示的 token 或 token 链。下面只展示一个块内的 KD 项，省略温度、跨块归一化和浮点保护。

D_{\mathrm{X}}=\sum_{v\in K_X}q_{t,v}\left(\log q_{t,v}-\log\htmlClass{t1}{p_{s\to t,v}^{M,K_X}}\right)
D_{\mathrm{CSD}}=\mathrm{JSD}_{1/2}\!\left(\htmlClass{t2}{p_s^{\mathcal E+\mathrm{REST}}},\htmlClass{t2}{p_t^{\mathcal E+\mathrm{REST}}}\right)

第一式的 p 是学生投影概率按块平均、再归一化的结果；q 是教师逐位置 log-softmax 按块平均、再取 exp 的分数，未再次归一化。因此不把 q 称为完整概率分布。块内聚合代码 与第二式的共同事件概率不是同一种处理。

X-Token 默认 P-KL 投影到教师词表；CSD 默认 JSD 比较共同事件和 REST。CSD 的完整 KD 按全局有效块数归一化，乘温度平方，非 1:1 块默认加权 ×5；之后 加入学生 CE。默认动态缩放用不求导的 CE/KD 幅度比缩放 KD。

选用时需要知道什么？

X-Token 默认 P-KLCSD
离线文件带权投影矩阵学生→教师、教师→学生的 token 序列映射表
传输完整教师 logits默认 top-K=128；K=0 用 dense
后端AutomodelAutomodel 或 Megatron；组合限制见指南

默认 K=128 表示每个位置主要发送教师概率最高的 128 个词项；它不只是省通信，也改变被比较的事件集，REST 保留剩余概率。后端与 packing 限制 需要一起满足。本轮发现两项正确性问题，分别见另外两页；CPU 验证不等于完成 GPU 资格验证。

本轮验证：CPU loss/梯度、真实 tokenizer 和配置检查；没有运行真实模型训练、GPU、CUDA IPC 或 NCCL。修复仅在内存中验证，未改 PR 生产文件。
